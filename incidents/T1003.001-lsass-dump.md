## Incident: Credential dumping via LSASS memory access (ATT&CK T1003.001)

> **Marquee incident.** Fill during Phase 2 when you detonate T1003.001. This skeleton is
> pre-written so you only drop in your evidence.

**Summary.** At <time>, host WIN-VM triggered detection rule <id> — a non-system process opened a
handle to `lsass.exe` with memory-read access, consistent with credential theft.

**ATT&CK.** T1003.001 (OS Credential Dumping: LSASS Memory) — Credential Access.

**Detonation / how it was produced.** `Invoke-AtomicTest T1003.001 -TestNumbers 1` (comsvcs.dll
MiniDump). Evidence: Sysmon EID 10, `SourceImage=…\rundll32.exe`, `TargetImage=…\lsass.exe`,
`GrantedAccess=0x1010`.

**Detection logic.** Sigma/Wazuh rule keys on **Sysmon EID 10** where `TargetImage` ends
`\lsass.exe` and `GrantedAccess` is in the memory-read set (e.g. `0x1010`, `0x1410`, `0x1438`),
excluding known AV/EDR `SourceImage`s.

**Triage steps (what an analyst does next).**
1. Confirm `SourceImage` lineage — is the caller signed / expected on this host?
2. Check for follow-on persistence and lateral movement from this host.
3. Isolate the host if the source is unsigned/unknown.

**False-positive analysis.** EDR/AV and some backup agents legitimately read LSASS; allowlist
their signed images. Documented exclusions: `<list>`.

**Recommended response / containment.** Isolate the host, rotate credentials that were resident,
hunt for lateral movement (4624 type 3/10 originating from this host).
