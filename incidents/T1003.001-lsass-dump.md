## Detection design & gap analysis: LSASS credential dumping (ATT&CK T1003.001)

> This is the **marquee** technique. In this lab it is a **documented gap**, not a live detection —
> the atomic never produced the telemetry the rule needs. Writing up *why*, honestly, is itself the
> point: a detection engineer who can explain a miss is worth more than one who claims 10/10.

**ATT&CK.** T1003.001 (OS Credential Dumping: LSASS Memory) — Credential Access.

**The detection (authored, deployed, ready).** Rule **100231** (`local_rules.xml`, level 12) keys on
Sysmon **Event ID 10** (ProcessAccess) where a process opens a handle to `lsass.exe` with a
memory-read access mask:
```xml
<rule id="100231" level="12">
  <if_group>sysmon</if_group>
  <field name="win.system.eventID">^10$</field>
  <field name="win.eventdata.targetImage" type="pcre2">(?i)\\lsass\.exe$</field>
  <field name="win.eventdata.grantedAccess" type="pcre2">(?i)^0x(1010|1410|1418|1438|143a|1fffff)$</field>
  ...
</rule>
```
The design is sound: the EID 10 handle-open is generated the moment a dumper *touches* LSASS —
the dump file succeeding is irrelevant, so the detection does not depend on the payload working.

**What was attempted.**
- `rundll32.exe comsvcs.dll, MiniDump <lsass_pid> ... full` (LOLBin MiniDump)
- `Invoke-AtomicTest T1003.001` (comsvcs test), Windows Defender real-time protection disabled.

**Why it did not fire (the gap).** No Sysmon **EID 10** targeting `lsass.exe` was ever generated —
the dumper was blocked *before* it could open a memory-read handle:
1. **LSASS protection / ASR.** Even with Defender real-time off, Windows LSASS run-as-PPL and the
   Attack Surface Reduction rule *"Block credential stealing from lsass.exe"* can prevent the
   handle open, so Sysmon never logs the ProcessAccess. Access was denied at the OS layer.
2. **Tooling friction.** The manual `rundll32` command was also mangled once by PowerShell's comma
   parsing (fixed with a `cmd /c` wrapper), and the mimikatz-based variant failed on a path error.

**How to close it.** Re-run on a VM where LSASS protection and the credential-theft ASR rule are
relaxed (or an EDR-off gold image), confirm a Sysmon EID 10 with `GrantedAccess` in the memory-read
set appears, and verify 100231 fires. If a live `GrantedAccess` value falls outside the current
mask list, widen the regex — that is a one-line tune, not a redesign.

**False-positive profile (for when it is exercised).** EDR/AV and some backup agents legitimately
read LSASS. The `100232` tune-down stub allowlists known signed readers (`MsMpEng.exe`,
`wazuh-agent.exe`) by `SourceImage`.

**Triage steps (analyst, once live).** Confirm the `SourceImage` lineage and signature; if unsigned
/ unexpected, treat as active credential theft — isolate the host, rotate credentials resident on
it, and hunt lateral movement (4624 type 3/10 originating from the host).
