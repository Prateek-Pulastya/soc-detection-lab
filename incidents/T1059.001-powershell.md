## Incident: Suspicious PowerShell execution — encoded command / download cradle (ATT&CK T1059.001)

**Summary.** On 2026-08-23, host `Victim` (agent 001, 192.168.198.130) triggered detection rule
**100201** (level 12) — a `powershell.exe` process launched with an `-EncodedCommand` argument,
consistent with a stager or an operator hiding intent behind Base64.

**ATT&CK.** T1059.001 (Command and Scripting Interpreter: PowerShell) — Execution.

**Detection / how it was produced.** `Invoke-AtomicTest T1059.001` plus a controlled repro:
```
powershell.exe -EncodedCommand RwBlAHQALQBEAGEAdABlAA==
```
Evidence — Sysmon **Event ID 1** (process creation):
- `data.win.eventdata.image` = `C:\WINDOWS\System32\WindowsPowerShell\v1.0\powershell.exe`
- `data.win.eventdata.commandLine` = `"...\powershell.exe" -EncodedCommand RwBlAHQALQBEAGEAdABlAA==`
  (Base64 decodes to `Get-Date` in this benign repro; a real stager would decode to a download
  cradle or in-memory loader).
- `data.win.eventdata.hashes` present; `data.win.system.channel` = `Microsoft-Windows-Sysmon/Operational`.

**Detection logic.** Rule 100201 keys on the **behaviour**, not any single IOC: a `powershell.exe`
/ `pwsh.exe` process whose command line contains an encoding or in-memory download indicator
(`-enc`, `EncodedCommand`, `FromBase64String`, `IEX`, `Invoke-Expression`, `Net.WebClient`,
`DownloadString`, `DownloadFile`, `DownloadData`). Validated against a varied second detonation
(a `Net.WebClient().DownloadString` cradle) — the rule still fired, confirming it detects the
technique rather than the atomic's filename.

**Triage steps (analyst).**
1. Decode the `-EncodedCommand` blob (`[Text.Encoding]::Unicode.GetString([Convert]::FromBase64String(...))`)
   and read what it actually does.
2. Check the `ParentImage` — was this spawned by `cmd.exe`/`explorer.exe` (interactive) or by an
   unexpected parent (Office, a service, a scheduled task)? Unexpected lineage raises severity.
3. If the decoded command reaches out to a URL, pull the destination and check it against threat
   intel; hunt Sysmon EID 3 (network) and EID 11 (file create) from the same process.
4. Isolate the host if the decoded payload is a real download/loader.

**False-positive analysis.** Encoded PowerShell is **dual-use** — admin tooling and legitimate
automation also base64-encode arguments or pull scripts from internal URLs. Tune with an allowlist
of the trusted caller by `ParentImage` (signed automation agent) and/or internal URL prefix; the
`100202` tune-down stub in `local_rules.xml` is the hook for that.

**Recommended response / containment.** Confirm intent from the decoded command; if malicious,
isolate the host, kill the process tree, capture the decoded payload and any downloaded artifact,
and hunt for follow-on persistence (Run keys, scheduled tasks) and lateral movement.
